`BuildNodeStepRow()` 헤더 7개 항목 요지:
1. 대상 범위 — 미등록 도로도 일반도로로 과금(구역 등록 여부 무관)
2. 산출 재료 — 게이트·등록길이 없이 전부 GPS 실측. OCCUR_DT 는 일반도로만 진출 시각
3. 한 레코드로 합쳐지는 3경로 — 구간단속 미러 인수인계 / 보류 1 tick 지연 / 폴리곤 접촉 소급
4. 누락 링크 복구와 FROM_ID/TO_ID — FROM_ID 는 "거리가 실제로 발생한 첫 링크"
5. CHARGE_YN/STATUS — 정상 Y/0, 미확정 N/3(AUDIT). 면제도로 N/4(SKIP)와 구분
6. 주정차 폴리곤 억제 — **매칭좌표 단독 기준**(원시좌표 아님), 4×4 판정표
7. 폴리곤 진출 run — **거리와 시간을 반드시 같은 기준점(경계)에서** 잰다

## 작업 시 지켜야 할 것

1. **변경 이력을 반드시 주석에** — 날짜·근거·**실측 트립 ID 와 seq**·되돌리는 법. 값만 바꿔도 근거를 남긴다.
2. **정본 주석 동기화** — 규칙이 바뀌면 `BuildNodeStepRow()` 헤더도 같이 고친다.
3. **결과는 개선율로** — 적용 전/후의 **매칭 성공율·정확도**를 나란히. 집계만으로 판단이 안 되면
   정답 불요 지표(이격거리·연결 정상률)를 함께 본다.
4. **원복·이슈는 ID 로 특정** — `trip_id` + `gps_seq`(맵매칭) / `trip_seq`(과금 이력).
5. **정확도 기준선은 스냅샷** — 갱신 시점 엔진 출력이 정답이 된다. 잘못된 매칭이 섞인 채 갱신하면
   그 오류가 영영 안 잡힌다. 갱신 전 보조 지표로 "지금이 이전보다 나은가"를 먼저 확인할 것.
6. **원격(운영) 반영은 전부 수동** — 로컬에서 테스트를 마친 뒤 사용자가 직접 시점·범위를 정해 반영한다(2026-10-04 사용자 지시). 엔진 작업은 로컬 빌드·로컬 재매칭까지만 하고, 반영 대상(파일·요지·검증 결과)을 정리해 넘긴다.

### 함수와 어긋나 있던 설명 블록 (제자리로 이동)

`AppendExpiredParkingCharge` / `AppendExpiredExemptZoneCharge` / `AppendExpiredClosedRoadCharge`
세 함수의 doxygen 이 각각 `InterpolateZoneCrossingTime` / `BuildExemptRow` / `ApplyZoneExitTailDist`
위에 붙어 있었다(2026-09-06 에 `AppendExpiredNodeStepCharge` 에서 같은 문제를 한 번 고친 전례가 있다).
