# 맵매칭 처리 분석 — 추가기능·로직 백로그 (2026-09-05)

MapMatchSvr 맵매칭 파이프라인 전수 분석 결과. 이 저장소의 미착수 설계는 별도 이슈
트래커가 아니라 **소스 주석에 근거·실측치와 함께 축적**되어 있다. 그것을 한곳에 모으고
착수 조건·우선순위를 붙였다.

기준 소스: `MapMatchSvr/src` 27,540줄, 커밋 `16690a7` (일반도로 이슈 보완)

## 1. 현재 파이프라인 (요약)

```

      ↓ 큐
RawLogWorker(×10)
  ValidateRawLog → NeedsBeginReset(세션 리셋) → ShouldSkipGpsInput(RAW_VLD/정확도)
      ↓
  ProcessManager::AttemptMatch          ① 적응형 반경(2.5×accuracy, 20~75m)
      ├ CContinueMapMatch (위상 그래프)  depth = maxstep(4) + 공백적응(최대 +3)
      │    비용 = 거리 + w_a·|방위각차|(cap 15m) + hop벌점(8m/hop)
      │           + 미연결 30m + 지리브릿지 5 + 고도 보조

      │          BridgeNearbyLinkStarts(15m 좌표근접 브릿지)

      ↓ ② 실패 시 반경 확대 재시도 → ③ 진단반경(250m) → ④ 기하 최근접
  8종 SKIP 강등 게이트 (RawLogWorker.cpp:3479~3610)
      역행 미확정 / 클램프 저신뢰 / 역행 판단불가 / 폴백 점프 비현실
      재구성경로 절대속도 / 경로 방향 / 구간 제한속도 / raw구역 폴리곤 이탈
      ↓
  1틱 지연 커밋(CommitPendingRow) — 다음 점을 보고 짝링크·경로불연속 보정
      ↓
  과금 5유형 판정(OPEN/CLOSED/SPEED/EXEMPT/NODE_STEP + PARKING)
      ↓
```

**A-1 상세 (가장 구체적인 미착수 설계)**
- 문제: 직전 링크 A의 종료 노드에서 지선 B와 본선 C가 갈라질 때, 차량은 A→C 직진인데
  한 틱만 짧은(8.9~12.6m) 중앙 크로스오버 지선 B에 붙는다. 그 시점 정보만으로는
  이격차 0.06~2.4m·방위각도 안 갈려 판별 불가 — **다음 점을 봐야 한다**.
- 조건: `hop(A→B) + hop(B→C) − hop(A→C) >= 4`
- 위치: `CommitPendingRow()` — 기존 1틱 지연 커밋 구조 재사용(추가 지연 없음)
- 안전장치: 재매칭 후보가 원래보다 15m 이상 멀면 원래 값 유지
- 실측 해당: 3건 / 전이 104건(2.9%), 실주행 11트립 1,355점 기준
- 착수 조건: 표본 3건으로 임계값을 정하면 과적합 — **실차 데이터 축적 후**
- 별개 유형: IC/램프에서 두 후보가 모두 좌표근접 브릿지로만 발견돼
  `MM_GEOM_BRIDGE_PENALTY`로 구별 불가한 케이스(미해결이슈 #1)도 같은 룩어헤드가 필요.
  단, 과거 "브릿지 링크를 TURNINFO 재발견 시 승격" 시도는 depth 지수폭증으로 즉시 롤백됨.

## 3. 우선순위 제안

1. **B-1 이중과금** — 유일한 아키텍처 결함이고 과금 금액에 직접 영향. 나머지는 정확도 개선.
2. **A-2 `hoppenalty_lenratio`** — 코드는 이미 있고 값만 결정하면 됨. 짧은 지선 누락 42.9%.
3. **B-2 ERROR 사유 저장** — 이후 모든 정확도 작업의 관측 기반. 컬럼 1개 추가로 끝남.
4. **A-1 룩어헤드** — 설계 확정. 실차 데이터가 쌓이는 대로 착수.
5. C 계열 — 운영 부하가 실제로 늘어난 뒤에 대응해도 되는 항목.

## 4. 이 코드베이스의 작업 원칙 (관찰)

- 모든 임계값에 **실측 근거와 트립 ID**가 주석으로 붙는다. 근거 없는 튜닝은 하지 않는다.
- 롤백 이력도 주석에 남긴다(연쇄 브릿지 차단, 속도게이트→수선거리 교체, 배율식 SKIP 승격).
- "확신 없는 매칭보다 SKIP" — 애매하면 MATCHED로 확정하지 않는다.
- 표본이 적으면 파라미터만 배선하고 기본값 0(비활성)으로 둔 뒤 데이터를 기다린다.
- 국소적 매칭 개선이 확정 과금 레코드를 훼손하면 개선을 포기한다(2026-09-04 판단).

## 5. BEGIN 각도 미참조 조사 (2026-09-05 추가)

### 사실관계

`SgmtMatch(..., bIgnoreHeading=true)` — 커밋 `9763f0e`(2026-08-20, 작업일 08-19).
주석에 **"각도 미참조 실험 … 임시"** 로 적힌 채 운영 중이고, **껐던 근거는 어디에도 기록이 없다**
(이 저장소 관례상 유일한 예외). 되돌리기 전 사용자 확인 필요.

### 왕복분리 진입부 SKIP 인과 (실측 000376_20260821095239 seq1~4)

| seq | 2040424401(역방향) | 2040424301(정답) | heading | 결과 |
|---|---|---|---|---|
| 1 | **1.8m** | 8.4m | 118° | SKIP |
| 2~4 | 2.6~4.2m | 5.7~7.5m | 82~86° | SKIP |
| 5 | 8.2m | **1.9m** | 83° | MATCHED |

거리만 보므로 역방향 채택 → 짝 링크 교정 실패 → `IsAntiHeadingOpposite` 거부권 → SKIP.
seq1 이 SKIP 인 트립이 21개 중 10개.

### 시도하고 폐기한 것

| 시도 | 결과 |
|---|---|
| `FixOppositePairByHeading` 발동 여부 확인 | **0건** — 짝 링크가 후보 목록에 없어 무력 |
| `FixReverseLinkByAzimuth` 신규(짝 의존 제거) | **지표 변화 0**, 발동 5건은 cost 6.8→74.9 악화 |
| seq1 에서 거리만(A) vs 각도 포함(B) 비교 | 대상 케이스 **A·B 동일**, 전체 4건만 변화·개선 0·악화 1 |

### 진짜 원인 — GRID 후보 탐색

seq1 의 Begin 후보 목록이 `n=1`(역방향 링크 하나뿐)이고 **정답 링크가 아예 없다.**
반경 75m 로 넓혀도 46.5m·51.4m 링크는 들어오는데 8.4m 짜리는 빠진다. 그 링크는 seq5 에서
1.9m 로 정상 매칭되므로 psf 에는 존재한다. **목록에 없으면 어떤 교정으로도 못 뽑는다.**
→ 다음 조사: `GetNearGridID` 인접 그리드 범위, `GRID_SGMT_INFO` 등록 방식.

### 곁가지 (미착수)

`SgmtMatch` 각도 판정은 세그먼트 방위각을 정·역 양방향으로 보고 유리한 쪽을 쓴다(2026-07-16,
양방향 단일 링크의 120° 오배제 방지). 그래서 역주행 링크도 각도차 44°로 통과한다.
왕복분리 링크(`qwOppositeLinkID != 0`)에 한해 역방향 fit 을 금지하면 그 부작용만 제거 가능.
