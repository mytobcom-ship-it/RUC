# 표준노드·링크 `TURNINFO` 전국 데이터 회전각 분석

- 작성일: 2026-08-22
- 분석 대상: `CreateData/data`의 `TURNINFO.dbf`, `MOCT_LINK`, `MOCT_NODE`
- 좌표계: EPSG:5186 기반 투영좌표(미터)
- 용도: 공식 코드 의미와 전국 원본 형상에서 관측된 회전각을 분리해 정리

## 1. 핵심 결론

1. `TURN_TYPE`은 회전각 코드가 아니라 **회전 허용·제한 유형 코드**이다.
2. `TURN_OPER`는 허용/금지가 아니라 **전일제(`0`)/시간제(`1`)**이다.
3. 공식 규격에는 코드별 각도 범위가 없다. 본 문서의 각도는 전국 원본 형상에서 **실측한 통계**이다.
4. 실측 결과는 공식 정의와 일치한다. `011`은 U턴, `101`은 좌회전금지, `102`는 직진금지, `103`은 우회전금지 형상이 대부분이다.
5. U턴과 P턴은 접선 각도만으로 구분할 수 없다. 원본 `TURN_TYPE`을 유지해야 한다.

## 3. 공식 코드와 전국 관측 각도

### 3.1 각도 정의

- 진입 벡터: `ST_LINK`에서 `NODE_ID`로 향하는 접선
- 진출 벡터: `NODE_ID`에서 `ED_LINK`로 향하는 접선
- 회전각: `atan2(cross(진입,진출), dot(진입,진출))`
- 범위: `-180° ~ +180°`
- EPSG:5186의 x=동쪽, y=북쪽 좌표에서 **양수는 좌회전, 음수는 우회전**이다.

형상 분류를 위한 분석용 임계값은 현재 `BinaryMaker.cpp`과 동일한 다음 값을 사용했다.

| 형상 분류 | 분석용 각도 기준 |
|---|---|
| 직진 | `|θ| ≤ 30°` |
| 좌회전 | `30° < θ < 150°` |
| 우회전 | `-150° < θ < -30°` |
| U턴형 | `|θ| ≥ 150°` |

> 이 임계값은 공식 `TURN_TYPE` 규격이 아니다. 형상 통계를 요약하기 위한 프로젝트 분석 기준이다.

### 3.2 코드별 요약

각도 통계는 노드와 진입·진출 링크 끝점의 거리가 모두 30m 이내인 43,399건을 신뢰 표본으로 사용했다. `P05·P50·P95`는 절대각 `|θ|`의 분위수이다.

| `TURN_TYPE` | 공식 설명 | 전체 건수 | 신뢰 표본 | `|θ|` P05 / P50 / P95 | 주요 형상 분류 | 해석 |
|---|---|---:|---:|---:|---|---|
| `001` | 비보호회전 | 14 | 13 | 77.4° / 91.8° / 158.3° | 좌회전 11건(84.6%) | 주로 비보 좌회전이지만 표본이 작고 U턴형 2건이 있음 |
| `002` | 버스만회전 | 4 | 4 | 78.6° / 95.5° / 106.3° | 좌회전 4건(100%) | 현재 자료는 모두 버스 전용 좌회전 형상이나 표본이 매우 작음 |
| `003` | 회전금지 | 5 | 4 | 91.2° / 137.4° / 147.8° | 좌 3건, 우 1건 | 특정 방향이 아닌 `ST_LINK→ED_LINK` 쌍 자체의 금지 |
| `011` | U-TURN | 27,825 | 27,401 | 159.8° / 180.0° / 180.0° | U턴형 27,258건(99.5%) | 전국 자료에서 U턴 형상이 명확함 |
| `012` | P-TURN | 3 | 2 | 174.4° / 177.0° / 179.7° | U턴형 2건(100%) | 접선 각도만으로는 U턴과 구분 불가, 표본도 매우 작음 |
| `101` | 좌회전금지 | 13,077 | 12,771 | 62.0° / 91.0° / 147.6° | 좌회전 12,300건(96.3%) | 대부분 좌회전 형상의 금지 쌍 |
| `102` | 직진금지 | 1,008 | 943 | 0.0° / 3.2° / 30.4° | 직진 890건(94.4%) | 대부분 직진 형상의 금지 쌍 |
| `103` | 우회전금지 | 2,282 | 2,261 | 59.7° / 94.4° / 145.4° | 우회전 2,202건(97.4%) | 대부분 우회전 형상의 금지 쌍 |

`001`, `002`, `003`, `012`는 표본이 3~14건에 불과하므로 관측 각도를 범용 기준으로 사용하면 안 된다.

### 3.3 `TURN_OPER` 분포

| `TURN_TYPE` | `TURN_OPER=0` 전일제 | `TURN_OPER=1` 시간제 | 합계 |
|---|---:|---:|---:|
| `001` | 14 | 0 | 14 |
| `002` | 1 | 3 | 4 |
| `003` | 5 | 0 | 5 |
| `011` | 27,822 | 3 | 27,825 |
| `012` | 3 | 0 | 3 |
| `101` | 13,073 | 4 | 13,077 |
| `102` | 1,007 | 1 | 1,008 |
| `103` | 2,280 | 2 | 2,282 |
| **합계** | **44,205** | **13** | **44,218** |

시간제는 13건으로 적지만 `TURN_OPER=1`을 영구 금지로 처리하면 시간의존적 정보를 잃는다. 현재 `TURNINFO.dbf`의 `REMARK`는 모두 비어 있어 실제 운영 시간대는 이 파일만으로 복원할 수 없다.

## 4. 분석 방법

1. `TURNINFO.dbf`의 44,218건에서 `NODE_ID`, `ST_LINK`, `ED_LINK`, `TURN_TYPE`, `TURN_OPER`를 읽었다.
2. `MOCT_NODE.dbf/.shp`에서 회전 노드 40,420개의 좌표를 읽었다.
3. `MOCT_LINK.dbf/.shp`에서 진입·진출 링크 73,803개를 찾었다.
4. 각 링크의 두 끝점 중 `NODE_ID` 좌표와 가까운 끝점을 교차 지점으로 선택했다.
5. 교차 지점과 인접 버텍스로 진입·진출 접선을 만들고 signed angle을 계산했다.
6. 불일치 영향을 줄이기 위해 노드–링크 끝점 거리가 모두 30m 이내인 건을 신뢰 표본으로 분리했다.

## 5. 데이터 품질과 한계

| 항목 | 건수/값 |
|---|---:|
| `TURNINFO` 전체 | 44,218건 |
| 각도 계산 성공 | 44,149건(99.84%) |
| `ST_LINK` 원본 누락 | 48건 |
| `ED_LINK` 원본 누락 | 21건 |
| 노드–링크 끝점 거리 30m 초과 | 750건 |
| 끝점 거리 중앙값 / P95 / P99 | 0.0m / 19.2m / 28.6m |
| 끝점 거리 최댓값 | 635.3m |

- 소실된 링크 참조 69건은 각도를 계산할 수 없다.
- 신뢰 표본에서도 일부 코드는 예상 형상과 다른다. 복잡교차로, 링크 분할, 짧은 접근 링크, 원본 구축 오차가 영향을 줄 수 있다.
- 링크의 첫 세그먼트만으로 계산한 국소 접선각이므로 교차로 전체의 주행 궤적과 다를 수 있다.
- P턴은 다수의 링크를 거치는 운행 개념이므로 단일 `ST_LINK→ED_LINK` 접선각만으로 판정하지 않는다.
- 회전각은 기하학적 방향을 보조하는 값이며, 허용·금지·차종·시간제 의미를 대체할 수 없다.

## 6. 구현 권장안

### 6.1 공식 규칙과 형상 분류를 분리

```text
official_turn_type : "001" | "002" | "003" | "011" | "012" | "101" | "102" | "103"
turn_oper          : "0" | "1"              # 전일제 | 시간제
geometry_turn      : STRAIGHT | LEFT | RIGHT | UTURN_LIKE
turn_angle_deg     : -180.0 ~ +180.0
```

`TURN_TYPE`을 숫자로 변환해 `011`을 `11`로 저장하지 말고 원본 3자리 문자열을 유지하는 것이 안전하다.

### 6.2 회전각이 필요한 경우

현재 전국 데이터는 다음 형상 분류를 실무적 초기값으로 사용할 수 있음을 보여 준다.

```text
|θ| ≤ 30°       -> STRAIGHT
|θ| ≥ 150°      -> UTURN_LIKE
30° < θ < 150°  -> LEFT
-150° < θ < -30° -> RIGHT
```

다만 이 값은 `TURNINFO`에 없는 일반 연결 링크의 형상 분류나 표시용으로 사용하고, 공식 회전 규칙의 판정은 `TURN_TYPE`과 `TURN_OPER`를 우선한다.

### 6.3 코드별 처리 방향

| 코드 | 권장 처리 |
|---|---|
| `001` | 회전 가능으로 유지하되 비보호 속성 보존 |
| `002` | 버스는 허용, 일반 차량은 제한 |
| `003` | 해당 `ST_LINK→ED_LINK` 쌍 제한 |
| `011` | U턴 가능 규칙으로 보존 |
| `012` | P턴 가능 규칙으로 보존; 각도로 U턴과 합치지 않음 |
| `101` | 해당 좌회전 쌍 제한 |
| `102` | 해당 직진 쌍 제한 |
| `103` | 해당 우회전 쌍 제한 |

`TURN_OPER=1`은 항상 제외하지 말고 시간대 정보를 확보할 때까지 “시간 미상의 시간제 규칙”으로 별도 관리해야 한다. 해당 13건의 서비스 정책은 보수적 차단, 경고 후 허용 등을 별도로 결정해야 한다.
