# 표준노드·링크 `TURN_OPER`·`TURN_TYPE` 규격 해석

- 작성일: 2026-08-22
- 대상 자료: 표준노드·링크 `TURNINFO`
- 전국 원본 회전각 통계: `doc/표준노드링크_TURNINFO_전국데이터_회전각_분석.md`

## 1. 결론

`TURNINFO` 레코드는 `NODE_ID`에서 `ST_LINK`(진입 링크)에서 `ED_LINK`(진출 링크)로 이동하는 회전 정보를 나타낸다.

- `TURN_TYPE`은 **회전 각도 코드가 아니라 회전 허용·제한의 유형 코드**이다.
- `TURN_OPER`는 **회전 허용/금지 플래그가 아니라 제한 운영 방식(전일제/시간제)**이다.
- 공식 규격은 `TURN_TYPE` 코드별 회전각 범위를 정의하지 않는다.
- 좌·우회전과 직진의 기하학적 방향은 `ST_LINK → NODE_ID → ED_LINK` 형상으로 별도 계산해야 한다.

## 2. 공식 코드표

### 2.1 `TURN_TYPE` — 회전제한유형

| 코드 | 공식 코드 정보 | 경로 탐색 시 기본 해석 |
|---|---|---|
| `001` | 비보호회전 | 조건부 회전 가능 |
| `002` | 버스만회전 | 버스만 회전 가능, 기타 차량 제한 |
| `003` | 회전금지 | `ST_LINK → ED_LINK` 회전 제한 |
| `011` | U-TURN | U턴 가능 정보 |
| `012` | P-TURN | P턴 가능 정보 |
| `101` | 좌회전금지 | 좌회전 제한 |
| `102` | 직진금지 | 직진 제한 |
| `103` | 우회전금지 | 우회전 제한 |

> `011`, `101`, `102`, `103`을 각각 직진, 좌회전, 우회전, U턴으로 해석하면 공식 규격과 다르다.

### 2.2 `TURN_OPER` — 회전제한운영

| 코드 | 공식 코드 정보 | 해석 |
|---|---|---|
| `0` | 전일제 | `TURN_TYPE`의 제한이 전일 운영됨 |
| `1` | 시간제 | `TURN_TYPE`의 제한이 특정 시간대에 운영됨 |

`TURN_OPER=0`을 “회전 허용”, `TURN_OPER=1`을 “회전 금지”로 해석하면 안 된다. 허용·제한의 종류는 `TURN_TYPE`에 들어 있고, `TURN_OPER`는 그 운영이 전일인지 시간제인지를 표시한다.

## 3. 회전각과의 관계

공식 문서에는 다음과 같은 각도 분류 표가 없다.

- 직진: `-30° ~ +30°`
- 좌·우회전: `30° ~ 150°`
- U턴: `150° ~ 180°`

위와 같은 임계값은 맵매칭·경로 탐색 구현이 채택할 수 있는 **프로젝트 자체 정책**이며, `TURN_TYPE` 공식 코드 값의 정의가 아니다.

회전각을 계산할 때는 다음을 명시해야 한다.

1. `ST_LINK`의 진행 방향으로 `NODE_ID`에 진입하는 벡터를 구한다.
2. `NODE_ID`에서 `ED_LINK`의 진행 방향으로 나가는 벡터를 구한다.
3. 두 벡터의 signed angle을 계산한다.
4. 좌·우 부호는 사용 좌표계와 구현의 각도 정의에 따라 검증한다.

## 4. 현재 `CreateData` 구현과의 차이

작성일 기준 다음 구현은 공식 규격과 다르므로 수정 전에 영향도 검토가 필요하다.

| 위치 | 현재 해석/처리 | 규격상 문제 |
|---|---|---|
| `CreateData/src/DataFormat.h` | `0=허용`, `1=제한` | 실제로는 `0=전일제`, `1=시간제` |
| `CreateData/src/BinaryMaker.cpp` | `11=직진`, `101=좌회전`, `102=우회전`, `103=U턴`으로 추정 | 공식 코드는 `011=U-TURN`, `101=좌회전금지`, `102=직진금지`, `103=우회전금지` |
| `CreateData/src/TurnInfoLoader.cpp`, `BinaryMaker.cpp` | `TURN_OPER=1`인 회전 쌍을 제한으로 판정해 바이너리에서 제외 | 시간제 제한을 항상 금지된 회전으로 오해하고 시간 정보를 손실할 수 있음 |
| `roadnet/docs/SCHEMA.md` | `011=직진`, `101=좌회전`, `102=우회전`, `103=U턴` | 공식 코드표와 불일치 |

### 권장 처리

- `TURN_TYPE`의 원본 3자리 코드를 유지한다. 숫자로 변환해 `011`을 `11`로 저장하면 출력·로깅·비교 시 원본 규격과 달라질 수 있다.
- 차종, 시간대, 비보호 회전을 지원하지 못하는 경로 탐색 포맷이라면 정책을 별도로 정한다.
- 시간제 제한의 실제 시간 정보가 원본 `REMARK` 또는 다른 배포 자료에 존재하는지 확인한 후 데이터 모델을 정한다.
- 자체 회전각 분류와 공식 `TURN_TYPE`을 다른 필드나 enum으로 구분한다.

## 6. 예시

```text
NODE_ID   = 1234567890
ST_LINK   = 1111111111
ED_LINK   = 2222222222
TURN_TYPE = 101
TURN_OPER = 0
```

위 레코드는 “좌회전 코드, 회전 허용”이 아니라, `NODE_ID`에서 `ST_LINK → ED_LINK` 이동에 대한 **좌회전금지가 전일제로 운영됨**을 뜻한다.
