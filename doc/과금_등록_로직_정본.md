## 1. 전체 처리 흐름

```
PRIM_RAWGPS (MATCH_STATUS=0)
  └ Fetcher: 0 -> 2(PROCESSING) 예약, (device, trip, seq) 순 정렬, hash(device_key) 로 워커 배정
      └ Worker (단말별 세션, 락 없음)
          ├ 입력 필터 (raw_vld / ACCURACY_M>50 / 비현실 속도 / 폴백 점프) -> SKIP
          ├ 맵매칭 (CONTINUE: 직전 링크에서 TURN_INFO 탐색 / BEGIN: 그리드 후보 거리 판정)
          ├ 주정차 판정 (현재 tick 기준, ProcessParkingCharge)
          └ 1 tick 지연 확정 (CommitPendingRow) -> 과금 5유형 순서 호출
                OPEN -> CLOSED -> SPEED -> EXEMPT -> NODE_STEP(일반도로)
      └ 배치 끝: Drop -> Merge -> 큐 적재 -> 워터마크 방출(TRIP_SEQ 부여)
          └ BEGIN; rawgps_update(1/3/4); charge_insert; COMMIT (실패 시 ROLLBACK 후 0 으로 반납)
```

- `match_status`: 0 PENDING / 1 MATCHED / 2 PROCESSING / 3 SKIP / 4 ERROR.
  2 에 묶인 행은 기동 시 `rawgps_recover`, 운영 중 `stale_recover`(stale_sec) 로 풀린다.
- 과금 함수는 **1 tick 늦게**(다음 확정 링크를 본 뒤) 호출된다. 주정차만 현재 tick 기준이라 한 tick 앞선다.
- `raw_vld` 는 "국내 좌표 범위 안" 여부이며 수집서버가 채운다. 엔진은 읽기만 한다.

## 2. 과금 유형별 대상·판정·등록 여부

`base_roadlink.road_kind` = `charge_type`. 구역 마스터는 `base_roadlink`(link_ids·coords),
게이트는 `base_tollgate`(I 입구 / O 출구 / B 겸용 / M 개방식), 주정차 최소시간은 `base_parking_fine`.

| 유형 | 대상 판정 | 진입 / 진출 | 행 생성 조건 | 정상 | 이상 |
|---|---|---|---|---|---|
| **0 일반도로** | 매칭 링크가 ① 미등록 링크 ② 일반도로(0) 구역 링크 ③ 게이트형(1·2·3)에만 등록됐고 그 유형 run 이 닫혀 있는 링크 (`IsLinkNodeStepEligible`) | 연속 주행 구간 = 한 행. 이탈은 `node_exitcnt`(3) 디바운스 | 마감 시 1행. 매칭 tick 이 하나도 없는 행은 버림 | Y/0 | SKIP 구간 직선추정 N/3(1·2), 강제마감 N/3(61/62) |
| **1 개방식** | 구역 링크에 매칭(링크 역인덱스). M 게이트는 통과 여부만 표시 | 링크 진입·이탈, 이탈 디바운스 | 마감 시 1행 | Y/0 (정상 진입이면 게이트 무관) | 트립이 구역 안에서 시작해 M 게이트 미통과 N/3(11), 경로복구분(12) |

| **3 구간단속** | 입구(I) 게이트 통과. 중간 진입은 run 을 열지 않음(그 구간은 일반도로) | 출구 게이트를 ① 맵매칭이 복구한 경유 링크 ② 현재 링크(진행거리) ③ 직전 링크 ④ **누락 링크 직접 복구(6홉)** 순으로 찾고, 모두 실패한 채 구역을 벗어나면(`zone_exitcnt`) "출구 미확인" / SKIP tick 원시좌표 | **진입·진출 게이트 모두 확인 + 평균속도 ≥ 제한속도**일 때만 SPEED 행. 제한속도가 등록돼 있으면 위반 여부와 무관하게 같은 구간을 **일반도로 미러 행(Y/0)** 으로도 등록 | Y/0 | 게이트 이상·출구 미확인이면 SPEED 행 미생성(일반도로 미러만, 제한속도 미등록이어도 미러는 생성) |
| **4 주정차** | 폴리곤 판정(원시·매칭좌표, 규칙 1~5 — 5절) | 진입 `park_entrycnt`(3) 연속, 이탈 `park_exitcnt`(3) 연속 | 체류 ≥ `base_parking_fine` 최소시간(현재 5분)일 때만 | Y/0 | 강제마감 N/3(61/62) |

- **게이트형(폐쇄식 2·구간단속 3) 거리·속도·체류시간**(2026-10-04 사용자 확정): 거리 = **진입 게이트 ~ 진출 게이트 사이 구역 선 길이**
  (`CalcZoneSpanM` — 두 게이트를 base_roadlink 선에 투영한 진행거리 차). 체류시간 = 진출 시각 − 진입 시각(게이트 통과 시각 보간,
  게이트에 tick 이 없어도 같은 방식 — 종전 유지). 평균속도 = 거리 ÷ 체류시간(최소 1초). 진입 게이트를 못 잡으면 실제 출발 지점을
  선에 투영해 진출 게이트까지(종전: 직선). 선이 없거나 게이트가 선에서 30m 넘게 떨어지면 종전 값(구역 등록 길이).
  구간단속 미러(일반도로) 거리도 같은 값. 개방식(1)은 M 게이트 하나라 대상 아님.
- 그 밖의 평균속도는 실측 거리 ÷ 실측 시간(최소 1초).
- OCCUR_DT: **일반도로만 진출 시각**, 나머지는 진입 시각.
- FROM/TO: 일반도로는 링크 ID, 개방·주정차·면제는 구역 road_id, 폐쇄·구간단속은 게이트 ID.
- 게이트·경계 지점이 직전 tick 매칭점에서 2m 이내면 앞뒤 레코드가 같은 GPS_SEQ 를 공유한다(정상).

## 4. 일반도로(0) 적재 규칙 요약

정본: `BuildNodeStepRow()` 헤더 7항목.

1. **미등록 도로도 일반도로로 과금한다.** 구역 등록 여부는 과금 여부의 기준이 아니다.
2. 산출은 전부 GPS 실측(거리·시간·평균속도). OCCUR_DT 는 진출 시각.
3. 한 레코드로 합쳐지는 경로: 구간단속 미러 인수인계 / 보류 1 tick 지연 / 폴리곤 접촉 소급.
4. 누락 링크 복구: 직전 확정 링크~이번 링크 사이를 `FindLinkPathBounded`(6홉)로 복구.
   FROM_ID = 거리가 실제로 발생한 첫 링크. 다른 과금유형(1·2·5) 링크를 만나면 거기서 멈춘다.
5. CHARGE_YN/STATUS: 정상 Y/0, 미확정 N/3.
6. 주정차 폴리곤과의 관계 — 5절 참고(2026-10-04 변경).
7. 폴리곤 진출 run 은 거리·시간을 같은 기준점(경계)에서 잰다.

그 밖의 등록 규칙:
- **게이트형 링크의 일반도로 계상**: 개방·폐쇄·구간단속에만 등록된 링크는 그 구역 run 이 닫혀 있는 동안 일반도로다.
- **연속 병합**(`MergeAdjacentNodeStepRows`): 같은 트립의 이어지는 일반도로 행은 한 tick 공백까지 하나로 합친다.
  단, 병합 결과가 다른 유형 행을 통째로 감싸면 합치지 않는다 — **주정차(4)·구간단속(3) 행은 예외(감싸도 합침)**.
  **구간단속 앞뒤 일반도로는 한 행**이다(2026-10-04 사용자 확정): 진입 앞 일반도로 + 미러(구간단속 구간 + 진출 후)
  → 예) 980015: 일반 2~25(594m) + 구간단속 6~19. 이를 위해 구간단속 통과 중·미러 보류 중에도 앞 일반도로 행을
  워터마크 큐에 보류한다(`CalcChargeWatermark` ⑤). 판정은 병합 규칙 그대로(한쪽이라도 비정상이면 전체 비정상).
- **커버리지 복구**(`FillUncoveredLinkRows`): 트립에서 지나갔지만 어느 행도 덮지 않은 미등록 링크를 인접 일반도로 행에 흡수.
  제외: 타 유형 링크, 주정차 폴리곤 안 링크(링크 형상의 50% 이상이 안), **트립 첫 tick 의 링크**.
- **출발 tick**(2026-10-04 사용자 확정): 트립 시작은 **일반도로·구간단속 링크에 매칭된 첫 tick** 부터.
  출발 후보 해소로 SKIP 된 tick 에서 시작한 run·보류·이월은 첫 유효 tick 으로 다시 잡는다(`ReanchorRunHead`).
  다른 구역에서 진출해 시작하면 게이트·링크 시작부터(종전), 다른 구역 진입으로 끝나면 경계까지(종전).
- **이탈 지점 보정**: run 이 끝날 때 마지막 링크의 끝 노드까지 채운다. 단, 개방·폐쇄·면제 링크는 채우지 않고,
  **구간단속 진입으로 끝나는 경우는 진입 게이트까지만** 채운다.

## 5. 주정차(4) 판정과 폴리곤 안 일반도로 — 2026-10-04 확정

정본: `ProcessParkingCharge()` 위 [정책 대조표] (A 현행 / B 확정 정책 / C 권장안 / D 영향 검토 / E 구현·검증).

### 5.1 주정차 판정 규칙(변경 없음)

| 규칙 | 원시좌표 | 매칭좌표 | 결과 |
|---|---|---|---|
| 1 | 폴리곤 안 | 매칭 실패 | 주정차 |
| 2 | 안 | 안 | 주정차 |
| 3 | 밖 | 안 (주행 중·신뢰 매칭) | 주정차 |
| 4 | 안 | 밖 (주행 중·신뢰 매칭) | 주정차 아님(통과). **정지(<1km/h)면 미적용 → 주정차** |
| 5 | 경계 밖 ACCURACY_M 이내 | 매칭 실패 | 주정차 (10 < ACCURACY_M ≤ 50) |

- "안"은 경계 밖 min(ACCURACY_M, `park_pad`=10)m 까지 포함. ACCURACY_M > `park_accmax`(50) 좌표는 판정 제외.
- 체류시간 = **진입 경계 ~ 진출 경계(경계라인 통과 시각 보간)**. 원시좌표로 보간이 안 되면(규칙3·여유로 "안"인 tick)
  "안" 판정에 쓴 매칭좌표로 보간한다(B9).
- 출발이 폴리곤 안이면 출발 tick 부터, 도착이 안이면 도착 tick 까지(B4).
- TTL·종료신호 없는 트립 전환으로 끝나면 **구역 안에서 마지막으로 관측된 tick** 까지, N/3(61/62).
  TTL 만료 시각은 쓰지 않는다(B10).
- 체류 < 최소시간(5분)이면 주정차 행을 만들지 않는다.

### 5.2 폴리곤 안 일반도로 등록 — **2026-10-04 E16 으로 변경**
> 작업 문서(결정 기록·검증 기준값·미결 항목): [주정차구역_일반도로_등록_로직.md](주정차구역_일반도로_등록_로직.md)
> **E16(사용자 확정)**: 폴리곤 안이라도 일반도로로 판정되면 **항상** 일반도로로 등록한다. 일반도로 run 은 폴리곤을 의식하지
> 않고 다른 도로와 똑같이 이어진다(폴리곤 안 억제·접촉 버퍼·폴리곤 통과 행·진출 경계 이월 비활성, 커버리지 복구의 폴리곤 안
> 링크 제외 해제). 폴리곤 안(매칭좌표) 정지 tick(속도<1)은 거리 누적에서 뺀다. 주정차 판정·등록은 그대로이며 두 행은 겹쳐도 된다(B6).
> 되돌리기: `MM_PARK_SUPPRESS_NODESTEP = true`. 아래 표의 "트립 종료" 행은 E16 이후 **도착 tick 까지** 일반도로로 바뀌었다.


| 상황 | 일반도로 | 주정차 |
|---|---|---|

## 6. TRIP_SEQ 규칙

- 트립별 **1..N 연속**, **GPS_SEQ(START_GPS_SEQ) 순**, **등록 후 변경 금지**(외부 과금서버가 60초마다 폴링).
- **TRIP_SEQ 는 SQL 로 처리하지 않는다 — 엔진이 확정할 때 번호를 붙여 INSERT 한다**(2026-10-04 사용자 지시).
  사후 재부여 SQL [trip_seqoff]/[trip_seqfin] 과 UpdateTripSeqOrder(), config 키는 삭제했다.
  주정차 폴리곤 안 일반도로 행도 같은 경로(큐 적재 → 방출 시 번호)다.
- 마감된 행은 바로 INSERT 하지 않고 세션 큐에 넣었다가, 앞자리에 행이 더 생길 수 없는 경계(워터마크)보다 앞선 행만
  꺼내며 번호를 부여한다(`ReleaseChargeQueue`). 트립 종료·TTL·서버 종료·트립 전환 시 전량 방출.
- 마감 경로는 모두 **Flush → 큐 적재(EnqueueChargeRows) → 방출(ReleaseChargeQueue)** 순서다.
- **이어 매기기(2026-10-04 확정)**: 워커가 세션에 없는 trip_id 의 배치를 받으면 `[trip_seqmax]`(읽기 전용
  `MAX(TRIP_SEQ)`)를 조회해 다음 번호부터 매긴다(`QueryTripSeqMax()` → `nEmitSeq` 시드). TTL 마감·엔진 재기동 뒤
  같은 트립이 이어질 때 1 부터 다시 매겨 PK 충돌로 행이 조용히 버려지던 결함 수정(980015 seq26~35 일반도로 212m).
  로그 `trip_seq continued from db!`.
- **충돌 감지**: 과금 INSERT 의 실제 적재 행 수가 요청보다 적으면 `[CHARGE_SEQ_CONFLICT]` ERROR 로그
  (trip_id·trip_seq 범위). 배치는 실패로 보지 않는다(재시도 중복과 구분 불가). 정상 흐름에서는 0건이어야 한다.

### 6.0 TTL 마감 (2026-10-04 확정 — 권장안 (가)(나)(다))
- (가) TTL 마감도 **[trip_end] 와 같은 UPDATE**(trip_end_dt·upd_dt 만)로 끝낸다. 이미 확정된 행의 판정을 바꾸지 않는다.
  열려 있던 구간만 각 마감 함수가 직접 판정한다(일반도로 N/3·61, 개방·폐쇄·주정차 N/3, 면제 N/4, 구간단속 미러 Y/0).
  종전 `[trip_abend]` SQL(빈 trip_end_dt 행 전부를 N/3·61 로 강등)은 삭제했다.
- (나) TTL 마감의 종료 시각은 **마지막 GPS 시각**(`dtLastGpsEventTime`, 없으면 벽시계). 경과 판정(ttl_sec)은 종전대로 벽시계.
- (다) 워커가 일감 없이 **60초** 대기하면 그 워커 스레드에서 `idle()` → `ExpireTtlSessions()` 를 돈다
  (`CThreadPoolWorker::run` 의 `waitTimed`, `Runnable::idle`, `CWorkerManager::idle` 위임). 세션은 워커 전용이라 같은 스레드에서만 다룬다.

### 6.1 과금서버와의 관계 · 시각 컬럼 (2026-10-04 확정)
- `charge_status`: 엔진은 **0 PENDING / 3 AUDIT / 4 SKIP** 만 쓴다. **1 PROCESSING / 2 CHARGED 는 과금서버 소유**다
  (과금서버는 60초 주기로 PENDING 행을 trip_seq 순으로 가져가 처리, 인덱스 `(charge_status, reg_dt)`).
- 워터마크 큐 덕분에 한 트립에서 이미 나간 trip_seq 보다 작은 번호가 나중에 생기지 않는다.
- `reg_dt` = 엔진 INSERT 벽시계(불변) — **trip_seq 를 붙이는 순간(`ReleaseChargeQueue`)에 찍는다**(2026-10-04 수정: 종전엔 행 생성 시각이라 큐에 보류됐던 행은 실제 INSERT 보다 앞섰음). `upd_dt` = **최종 수정 일시(벽시계)**.
  **trip_seq 가 확정되어 INSERT 되는 시점에는 reg_dt = upd_dt** (2026-10-04 사용자 확정). 이후 마감 UPDATE([trip_end], TTL 마감도 같은 SQL) 시 NOW().
  INSERT 이후 행을 고치는 주체(엔진 마감 처리, 과금서버 상태 변경 0→1→2, 수동 수정)는 모두 그 시점에 upd_dt 를 갱신하는 것으로 본다(2026-10-04 사용자 판단). 엔진은 upd_dt 를 판정에 쓰지 않는다.
  두 컬럼을 나눈 취지: reg_dt 는 "언제 들어왔나"(과금서버가 새 행을 등록 순으로 가져가는 기준), upd_dt 는 "마지막으로 언제 바뀌었나"(가져간 뒤 바뀐 행 추적).
  트립 종료 시각은 `trip_end_dt`(GPS 시각)에만 둔다. (종전: 0·5 유형은 occur_dt, 정상종료 시 GPS 종료시각으로 덮음 → 수정일시가 등록일시보다 앞서는 모순)
- `[trip_end]`(정상 종료: trip_end_dt·upd_dt)는 **과금 INSERT 와 같은 배치 트랜잭션**에서 실행한다(종전: COMMIT 뒤 best-effort → 실패 시 trip_end_dt 영구 NULL 가능).
- TTL·비정상 마감은 판정 컬럼(charge_yn/status/non_charge_reason)을 **어떤 행이든** 다시 쓰지 않는다(6.0 (가)). 따라서 과금서버 소유 1·2 행도 건드리지 않는다.
  (종전 `[trip_abend]` 는 1·2 보호만 하고 0·3·4 행은 N/3(61) 로 강등 → 2026-10-04 삭제)
  (2026-10-04: 트립 전환 경로에 큐 적재가 빠져 이전 트립 행이 새 트립 번호를 받던 결함 수정)

## 9. 작업 원칙

1. **변경 이력은 소스 주석에** — 날짜·근거·실측 트립 ID·seq·되돌리는 법. 정본 주석과 이 문서도 함께 갱신.
2. **결과는 개선율로** — 적용 전/후 매칭 성공률·정확도, 과금은 유형별 행수·거리를 나란히.
3. **이슈는 ID 로 특정** — 맵매칭은 `trip_id + gps_seq`, 과금은 `trip_id + trip_seq`.
4. **원격(운영) 반영은 전부 수동** — 2026-10-04 변경분은 바이너리와 함께 **`MapMatchSvr/bin/query.sql`**([trip_end]·[trip_seqmax], [trip_abend] 삭제)과 **`MapMatchSvr/bin/config.ini`**([sql] `trip_seqmax=trip_seqmax`, `trip_abend`·`trip_seqoff`·`trip_seqfin` 키 삭제)도 반영해야 한다. config.ini 는 운영 접속정보를 유지한 채 해당 키만 고친다.
    — 로컬에서 빌드·재매칭·검증을 마친 뒤 담당자가 시점·범위를 정해 직접 반영한다.
   반영 시에는 바뀐 파일·요지·검증 결과를 함께 넘긴다. 설정(config.ini·query.sql)이 바뀌지 않았다면 바이너리 교체만으로 된다.
5. **맵매칭 소스는 git 이 정본** — 결과가 이상하면 DB·설정부터 확인하고, 소스 변경은 근거와 함께.
