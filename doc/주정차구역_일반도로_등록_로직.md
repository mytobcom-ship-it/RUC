# 주정차 단속구역 내 일반도로 등록 로직 — 작업 문서

> 주정차 단속구역(폴리곤) 안에서 일반도로로 판정된 주행을 과금/비과금 테이블(`ruc.prim_chargehand`)에 등록하는 로직을
> **기록하고 보완해 가는 작업 문서**입니다. 다른 PC에서도 `git pull` 후 이 문서부터 읽고 같은 기준으로 이어서 진행합니다.
> 과금 유형 전체 규칙의 정본은 [과금_등록_로직_정본.md](과금_등록_로직_정본.md)이고, 이 문서는 그중 주정차 구역 안 일반도로만 다룹니다.

## 0. 문서 운영 규칙

1. **작업 시작 전**: `git pull` 다음에 이 문서와 정본 5절을 읽습니다. 소스 주석 `[정책 대조표]`(`RawLogWorker.cpp`의 `ProcessParkingCharge()` 바로 위)도 같은 번호(B·E)로 관리합니다.
2. **로직을 바꾸면 같은 커밋에서** 다음 세 곳을 함께 고칩니다. 그래야 다른 PC가 pull했을 때 소스와 문서가 어긋나지 않습니다.
   - 이 문서: 4절(현재 로직), 6절(결정 기록), 9절(변경 이력)
   - 정본 문서 7절
   - 소스 정책표 주석
3. **결정 전 항목**은 8절에 두고, 결정되면 6절로 옮깁니다. 기존 기록은 지우지 말고 상태만 바꿉니다(예: "B4 → E16으로 대체").
4. **결과 보고**는 적용 전·후 수치를 나란히 적습니다. 행은 `trip_id + trip_seq`(과금)나 `trip_id + gps_seq`(맵매칭)로 특정합니다.
5. **운영(원격) 반영은 사용자가 직접(수동)** 합니다. 이 문서에는 반영 대상 파일만 적습니다.
6. 한글 파일명이 `\354\243\274...`처럼 보이면 `git config core.quotepath false`를 설정합니다.

## 3. 현재 로직 — 기존과 같은 부분 (2026-10-04 소스 기준)

### 3.1 주정차 구역 판정 (charge_type 4, `ProcessParkingCharge`)

| 항목 | 동작 |
|---|---|
| 대상 구역 | `ruc.base_roadlink`에서 `GEOM_TYPE='POLY'`, `USE_YN='Y'`인 것 |
| 대상 tick | GPS 좌표가 NULL이 아닌 **모든 tick**. 매칭 성공 tick뿐 아니라 RAW_VLD=false, 정확도 초과 SKIP, 트립 종료 tick도 포함합니다(호출 4곳). |
| 안 판정(기본) | 원시좌표가 폴리곤 안이거나 경계에서 `park_pad`(10m) 이내. 정확도가 pad보다 작으면 정확도만큼으로 좁힙니다. |
| 안 판정(매칭좌표 보완) | 매칭이 신뢰되고 주행 중(속도 ≥ 1)이면 매칭좌표가 안인 구역도 포함합니다. |
| 통과 배제 | 매칭이 신뢰되고 주행 중인데 매칭좌표가 그 구역 밖이면 그 구역은 제외합니다(옆 도로 통과). |
| 오차 구제 | 매칭 실패이고 정확도가 `park_accmax`(50m) 이하이면서 pad보다 크면, 반경을 정확도까지 넓혀 판정합니다. |
| 정확도 불량 | 정확도가 50m를 넘으면 그 tick은 판정·갱신 모두 건너뜁니다(트립 종료 tick은 예외). |
| 진입 | "안" tick이 `park_entrycnt`(3)번 연속되면 run을 엽니다. 진입 시각은 경계선 통과 시각으로 보간합니다(원시좌표, 안 되면 매칭좌표). |
| 체류 거리 | 원시좌표 사이 직선거리를 누적하되, 정차 tick(PARKED이고 속도 < 1)은 뺍니다. |
| 진출 | "밖" tick이 `park_exitcnt`(3)번 연속되면 확정합니다. 종료 시각은 경계선 통과 보간(B9)이고, 재진입 유예는 없습니다. |
| 등록 조건 | 체류시간이 `MIN(base_parking_fine.from_min)`×60초(현재 5분) 이상일 때만 INSERT합니다. 미만이면 행을 만들지 않습니다(비과금 행도 없음). |
| 판정 값 | 정상 진출·트립 종료는 Y/0입니다. TTL은 N/3(61), 종료 신호 없음은 N/3(62)이며 둘 다 구역 안 마지막 tick까지입니다(B10). `park_ttl`(600초)은 마지막 신뢰 tick 기준 Y/0입니다. |

### 3.2 일반도로(charge_type 0) 공통 규칙 — 폴리곤과 무관하게 그대로

- 연속 주행 구간 하나가 한 행입니다. 이탈은 `node_exitcnt`(3) 디바운스로 확정하고, 이어지는 행은 병합합니다(`MergeAdjacentNodeStepRows`).
- 출발은 일반도로·구간단속 링크에 매칭된 첫 tick입니다(E14). 다른 구역에서 나와 시작하면 게이트·링크 시작부터, 다른 구역에 들어가며 끝나면 경계까지 잽니다.
- 거리는 tick 사이 매칭점 직선 합입니다. 링크가 떨어져 있으면 누락 링크를 복구해 더하고, 역행 의심 tick과 원시좌표·방향이 같은 tick은 누적하지 않습니다.
- trip_seq는 START_GPS_SEQ 순으로 엔진이 확정할 때 부여합니다(워터마크 큐). reg_dt와 upd_dt는 INSERT 시각입니다.

## 4. 현재 로직 — 바뀐 부분 (E16, 2026-10-04)

| 항목 | 변경 전 (B2·B4) | 변경 후 (E16) |
|---|---|---|
| 폴리곤 안(매칭좌표) 일반도로 run | 억제·보류하고 안쪽 이동은 접촉 버퍼에 따로 누적 | **억제 없음** — 다른 도로와 똑같이 이어짐 |
| 주행해서 빠져나옴 | 안쪽(마지막 안쪽 tick까지) + 진출 쪽(경계부터)을 따로 만들어 병합 | 한 run으로 자연히 이어짐 |
| 구역 안에서 트립 종료 | 진입 경계까지만 | **도착 tick까지** |
| 커버리지 복구(`FillUncoveredLinkRows`) | 링크 형상의 50% 이상이 폴리곤 안이면 제외 | 제외하지 않음 |
| 주차 중 GPS 흔들림 | 접촉 버퍼에서 속도 < 1 tick 제외 | 일반 run에서 **폴리곤 안 속도 < 1 tick**을 거리 누적에서 제외 |
| 주정차 행 | 판정·등록 | 그대로(겹침 허용, B6) |

- 스위치: `RawLogWorker.cpp` 파일 상수 `MM_PARK_SUPPRESS_NODESTEP`. 지금은 `false`이고, `true`로 바꾸면 B2·B4 동작으로 돌아갑니다.
- 그대로 둔 코드: 접촉 버퍼, 폴리곤 통과 행, 진출 경계 이월 블록은 스위치가 false면 동작하지 않습니다. 되돌릴 때를 대비해 지우지 않았습니다.

## 7. 검증 절차와 기준값

**도구** (`web/tools/zone_check/analysis/`):

| 도구 | 용도 |
|---|---|

**수정 전 엔진과 비교하는 방법:**
1. `git worktree add --detach <임시경로> <커밋>`으로 비교할 커밋을 꺼냅니다.
2. 그 `MapMatchSvr/src`에서 `make install`을 실행하고, `link.psf`를 그 `bin/`에 복사합니다.
3. `cmp_run.sh`를 두 엔진에 각각 돌린 뒤 결과를 diff합니다.
4. 끝나면 `git worktree remove`로 정리합니다.
5. `cmp_run.sh`는 엔진을 내린 채 끝나므로 `run_svr.sh`로 다시 띄웁니다.

> 주의: `cmp_run.sh`는 실주행 트립의 과금 행을 지우고 다시 처리합니다. **운영 DB에서는 쓰지 마세요.**
